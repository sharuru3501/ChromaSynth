# ピアノロール設計(ティック分解能 + グリッド分割)

目的: 三連符などを **コマンドではなくUI(グリッド分割の切替)で入力**できるピアノロールを、
ゲームボーイの制約(CPU 約 1MHz 相当、VBlank 約 1140 サイクル、WRAM 8KB、SRAM 8KB)に無理なく載せる。

## 1. 時間分解能: 1拍 = 12 ティック

| 分割 | ティック/セル | 備考 |
|------|---------------|------|
| 1/4   | 12 | |
| 1/4T  | 8  | 4分三連 |
| 1/8   | 6  | |
| 1/8T  | 4  | 8分三連 |
| 1/16  | 3  | 既定 |
| 1/16T | 2  | 16分三連 |
| 1/48  | 1  | 微調整(最小単位) |

- 12 = 3×4 なので、2連系も3連系も**整数ティック**になる。32分音符(1.5ティック)だけは表せない(割り切り)。
- 24 ppqn(MIDI クロック)にしなかった理由: 192 ティックが 8bit に収まらなくなり、全コードが16bit化して重くなる。
  将来の MIDI クロック同期は **2クロック = 1ティック** で受ければよい。
- パターン長は最大 **192 ティック = 4小節(4/4)**、ループ長は1小節(48)単位で 48〜192。

## 2. 再生: 1フレームに高々1ティック

- 1ティックのフレーム数 = 5 × 59.7275 / BPM。BPM 240 で 1.244、BPM 60 で 4.98。
- 最短でも 1フレームより長い(= 318/256 フレーム)ので、**1フレームに2ティック来ることはない** → ループ不要、毎フレームの処理は一定。
- 端数は 8.8 固定小数のアキュムレータで持つ(`TempoTable`, `tools/gen_tempo.py`)。
- 発音のタイミング精度は「フレーム境界(16.7ms)に丸まる」。これは従来(ステップ再生)と同じで、LSDj など他のGBトラッカーと同水準。
  タイマ割り込みで精密化すると、ISR内でAPUを触る必要が出てメインループのビブラートと競合するため採らない。

## 3. データ: 1ティック = 1セル(1バイト)

- セル: `0`=空 / `$FF`=ノートオフ / それ以外=MIDIノート(ノートオン)。音は次の非空セルまで鳴る(= バーの長さ)。
- `wPattern[ch*256 + tick]`。**256バイト境界 + チャンネルごと256バイト**なので、アドレスは `H = HIGH(wPattern)+ch, L = tick` だけ。16bit演算が要らない。
- 容量: 4ch × 256B = 1KB(192ティック分のみ使用、残りは余白)。保存データも約 1.1KB(SRAM 8KB に余裕)。
- 旧形式(16分=1ステップ)との対応: 1ステップ = 3ティック。

## 4. 表示: グリッド(小節・拍)は固定、サブグリッド(分割)だけが変わる

小節と拍はティックで決まる固定の目盛りで、分割は「その中を何等分して列にするか」だけを決める。
**1ページは必ず拍の境界から始まり、整数拍を表示する**ので、分割を切り替えても小節の位置は動かない。

| 分割 | ティック/列 | 列数/ページ | ページ幅 | 1小節あたりの列 |
|------|-------------|-------------|----------|-----------------|
| 1/4   | 12 | 16 | 4小節 | 4 |
| 1/4T  | 8  | 12 | 2小節 | 6 |
| 1/8   | 6  | 16 | 2小節 | 8 |
| 1/8T  | 4  | 12 | 1小節 | 12 |
| 1/16  | 3  | 16 | 1小節 | 16 |
| 1/16T | 2  | 12 | 半小節(2拍) | 24 |
| 1/48  | 1  | 12 | 1拍 | 48 |

- 画面は最大16列。ページが16列に満たない分割(12列)では右側の列を空白にする(時間を持たない列)。
- 1/16T と 1/48 は1小節が16列に収まらないので、小節の一部(半小節・1拍)を1ページとして見る。ページ送りで続きを見る。
- ページ幅は全て 192 ティックの約数なので、ページはパターンをぴったり分割する(端数ページなし)。`tools/gen_divs.py` が検証する。
- 線は3段階: **小節線**(濃い紺)、**拍線**(中間の青)、**サブグリッド線**(薄い、列ごと)。どの分割でも小節線・拍線は同じティックに引かれる。
- ルーラー: 小節の頭に**小節番号**(1〜4)、それ以外の拍に点。ループ終端より後は何も出さない。右端は反転タブでページ番号。
- 分割を切り替えてもカーソルのティック位置は保つ(新しい分割の格子へ切り捨て)。ページは「カーソルを含む拍揃いのページ」になる。
- 細かい分割で置いた音を粗い分割で見ると、音は「その音の頭を含む列」から「終わりを含む列」までのバーとして描く(近似表示)。編集は常に現在の分割の格子上で行う。
- ページ位置の更新に割り算は使わない: ページ番号 = カーソルセル ÷ 列数 をループの引き算で求め(最大16回)、ページ先頭のティック/セルは足し算で求める。

### 列の要約(`BuildCols`)
各列について「鳴っている音程」と「頭か」「拍の線か」を先に要約する。1列ごとに:
1. 列の先頭ティックで鳴っている音(ページ先頭までは逆スキャンで求める)。
2. 列のスパン内にノートオンがあれば、最初のものを頭として表示。
3. スパンの最初のティックがOFFなら空列。
行の描画は、この16列の要約を表引きするだけになる。最悪でも 192(逆スキャン)+192(順スキャン) ティックの走査で、約 5k サイクル。

## 5. 描画とVBlank予算(重くしないための分担)

| 処理 | 場所 | 最大量 | サイクル目安 |
|------|------|--------|--------------|
| グリッド行の描画 → シャドウマップ | メインループ(VBlank外) | 8行/フレーム | 約 750/行 |
| ルーラー行・ステータス行の組み立て | メインループ | 変更時のみ | 〜600 |
| シャドウ → VRAM コピー(行) | VBlank | 2行(再生ヘッド移動時は1行) | 約 120/行 |
| ルーラー/ステータス → VRAM | VBlank | 各20バイト | 約 130 |
| 再生ヘッド(OAM) | VBlank | 16スプライト×X座標のみ | 約 160 |

- VBlank は約 1140 サイクルしかないため、**VBlankでは「コピーするだけ」**にする。文字列や数値の組み立てはVBlank外でバッファに作る。
- `UpdateUI` は入口で LY を見て、VBlank序盤でなければそのフレームの描画を見送る(フラグ駆動なので次フレームに回るだけ)。
- 編集は「変わった行だけ」再描画する(列要約の旧/新を比較)。目標: 押してから画面反映まで 4 フレーム以内(実測 3)。
- ページ送り・分割切替・チャンネル切替は全行(16行)を再描画: 描画は2フレーム、コピーは8フレーム(約0.13秒)。

## 6. 再生ヘッド: ティック単位で滑らかに

- スプライト16個を縦に並べた赤い線(OBJ パレット)。X座標だけを毎フレーム書き換える(Yは出現時のみ)。
- X = floor(dt × 8 / 分割ティック)(dt = 現在ティック − ページ先頭ティック)。割り算は避け、分割ごとの**早見表**(`PlayX*`, `tools/gen_divs.py` 生成、ページ幅ぶんのエントリ、計516バイト)を引く。
- 拍頭のティックでは X が列の左端(拍の線)にぴったり重なる。

## 7. 操作(シーケンサ画面)

| 操作 | 内容 |
|------|------|
| 十字キー(押しっぱなしでリピート) | カーソル移動(1セル / 1音程)。B押しながら=4セル / 1オクターブ |
| **B押しながらA**(同時でも可) | **グリッド分割を次へ切替**(1/4 → 1/4T → 1/8 → 1/8T → 1/16 → 1/16T → 1/48 → 1/4…)。先にAを押すと音が置かれてしまうので、Bを先に |
| A | 現在の分割1セル分の音を置く(試聴) |
| A押しながら ←→ / ↑↓ | 音の長さを1セル分だけ短く・長く / 移調 |
| B(タップ) | 音を削除 |
| SELECT単押し | チャンネル切替 |
| SELECT+↑↓ / ←→ | BPM ±1 / ループ長 ∓1小節 |
| SELECT+START | 再生/停止 |

三連符の入力例: `B`を押しながら`A`で 1/8T にする → `A` で置き、`→` `A`、`→` `A`(各セルは4ティック)。

## 8. やらないこと(複雑さ・負荷に見合わない)
- 32分音符(1.5ティック)、スウィング、ポリメトリック(チャンネルごとに別ループ長)。
- チャンネルごとの別分割。分割は画面全体で1つ。
- 1フレームに複数ティックを処理するループ(上記の通り発生しない)。
