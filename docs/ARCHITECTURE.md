# ARCHITECTURE

## 全体像
```
 [BLEキーボード/DAW] --BLE MIDI--> [ESP32ブリッジ(最終)] --\
 [USB/DIN MIDI機器] ------------> [マイコン(まず有線)] -----+--リンクケーブル--> Chromatic(カート: ChromaSynth ROM)
```
ROM は MIDI のトランスポートに依存しない。「リンクポートで届くMIDIバイト列」だけを扱う。
BLE は後付けでブリッジ側(ESP32)に実装する。

## ROM 内部
- `main.asm`: ベクタ/ヘッダ/初期化/メインループ/ISR/MIDI解析/ジョイパッド/発音(M0)
- 割り込み: VBlank(フレームフラグ), Serial(受信バイトをリングバッファへ)
- メインループ: `halt` → MIDI drain(毎回) → VBlank時のみ ジョイパッド + UI + シーケンサ tick
- ボイス: 4ch(パルス×2、ウェーブ、ノイズ)。当面は CH1 のモノ発音。

## 今後のモジュール分割(予定)
| ファイル | 内容 |
|----------|------|
| `apu.asm` | チャンネル抽象化、パッチ適用、エンベロープ/ビブラート/アルペジオのフレーム更新 |
| `midi.asm` | 受信パーサ、チャンネル→ボイスのアロケート、MIDI OUT キュー |
| `seq.asm` | パターン/ソング、再生位置、テンポ(VBlank 基準 or Timer)、MIDI clock 同期 |
| `ui.asm` | 画面描画(BG タイルのテキスト)、画面遷移(Play / Patch / Sequencer。Song は将来) |
| `sram.asm` | パッチ・パターンの保存(MBC5+SRAM) |

## データ構造
- Patch(実装済み, `wPatch`): 1chあたり32バイト×4ch + MIDI 設定の 32 バイト。レイアウトは `inc/synth.inc`(`P_*` の定数)と `src/ui.asm` のパラメータ表(`PT_*`、行 = バイト、ROM バンク 1)が定義元。バイト 22-31 は空き。
  - 共通: 0 main(duty/wave/width) 1 vol 2 edir 3 epac 4 len 5 pan 6 vibd 7 vibs / CH1: 8-10 sweep / CH4: 11 ndiv / CH1-3: 16 arp1 17 arp2 18 arps 19 slid / CH1-2: 20 dut2 21 dspd
  - 効果(M9b)は `TickChannel`(毎フレーム)から: `EffectsTick` がアルペジオ(`wBase` を書き換え、`wTickOn` で書き込ませる)とデューティの切り替え(NRx1)、`GlideStep` がスライド(`wGlide` を周期のオフセットとして足し、毎フレーム `>> SLID` ずつ 0 に近づける)。`NoteOn` は直前に鳴っていた音と周期を覚え、`EffectsStart` がレガートならスライドを始める。
  - `wPatch` は256バイト境界に置き、オフセット加算が桁上げしない前提でコードを書いている。
  - 音の長さ(LEN)を使うチャンネルは `wLenBit` に `$40` を持ち、NRx4 を書くたび(ビブラートなどの非トリガの書き込みも)にこのビットを立てる(0 で書くとレングスカウンタが止まるため)。
  - パンニング(NR51)と全体の音量(NR50)は、`VoiceTick` の後の `ApplyMixer` が毎フレーム音色から書く。
- ビブラート: 毎フレーム(VoiceTick)、発音中の CH1-3 の period を三角波で ±off。off は (2048-period) に比例させて音程に依存せず一定のセント幅になるよう近似。
- 画面: Play / Edit / Roll の3画面。画面切替は VBlank 直後に LCD を一瞬オフにして BG マップを作り直す。
- ピアノロールの描画(`src/roll.asm`): VBlank は約1140サイクルしかないので2段構え。
  1. メインループ(VBlank外)で `RenderPending` が最大4行を `wGrid`(シャドウタイルマップ)に描き、コピー要求フラグを立てる。
  2. VBlank直後に `UpdateSeq` が最大2行(再生ヘッドが動いたフレームは1行)をVRAMへコピーし、再生ヘッドのスプライトを動かす。
  変更が起きたら `MarkRowRender`/`MarkAllRender` で行にフラグを立てるだけ。画面は数フレームで追いつく。
  編集(置く/消す/長さ/移調)は `RollRefresh` が旧列要約と新列要約を比べ、変わった行(+カーソル行)だけを再描画する(押してから約3フレーム)。ページ送り・表示窓の移動・チャンネル切替・ロードは `RollRefreshAll` で全行。
  表示ページの各列「鳴っている音程」は `BuildCols` が先に要約(`wColPitch`/`wColHead`)するので、行の描画は表引きだけで済む。
- `UpdateUI` は入口で LY を見て、VBlank序盤(144〜146)でなければそのフレームの描画を見送る(フラグ駆動なので次フレームに回るだけ)。
- 再生ヘッド: スプライト16個を縦に並べた赤い線。移動時はX座標だけ書き換える。BG/OBJ パレットは `InitPalette`。
- Pattern(実装済み, `wPattern`): 4ch × 256バイト、1ティック=1セル(1拍=12ティック、最大192ティック=4小節)。0=空, $FF=ノートオフ, それ以外=MIDIノート。アドレスは `H=HIGH(wPattern)+ch, L=tick`(16bit演算なし)。ループ長は `wSeqLen`(ティック、48の倍数)。詳細と数字の根拠は [ROLL_DESIGN.md](ROLL_DESIGN.md)。
- シーケンサのタイミング: 毎フレーム 8.8固定小数のアキュムレータに +1.0。BPMごとの「1ティック=何フレーム」を `TempoTable`(`tools/gen_tempo.py` 生成)から引き、超えたら1ティック進める。最短でも1.244フレーム(240BPM)なので1フレームに複数ティックは来ない。
- 将来 MIDI clock 同期(M6)をする時は、このアキュムレータの代わりに 24ppqn のクロック(2クロック=1ティック)でティックを進める。
- Song: パターン番号の並び(未実装)
- 曲(M14・M19, `src/song.asm`、`src/pool.asm`): パターン 16 個、各パターンは最大 2 つの**区画(セグメント)**(4 小節ぶん = 4 チャンネル × 256 バイトのページ、192 ティックを使う)を持つ。区画は、WRAM のバンク 1〜7(4 KB ずつ、区画 28 個)の**共有の置き場(プール)**から、中身がある半分だけ借りる(`wPatSeg`)。借りていない半分は、全部 0 の予約区画(27 番)を読む。区画 `n` は、バンク `1 + n/4`、チャンネル c のページは `$D0 + (n mod 4)*4 + c`、ティック t の番地は `ページ*256 + t`。**パターンの中身を触るルーチンは、冒頭で SVBK を自分で決める**(`SegLoc`)。書くときは `EnsureSeg` で借りてから(`AbsHLW`)。設計は [M19_PATTERN_POOL.md](M19_PATTERN_POOL.md)。
- 保存(実装済み, `src/sram.asm`): SRAM(128KB、LSDj と共有)の**最後の 4 バンク(12〜15)**に 8KB × 4 スロット(スロット n はバンク 12+n の `$A000`)。1 スロット = `"CSYN"`+版数(`SAVE_VERSION` 9)+パッチ 160+チェーン 16+BPM+ループ長(小節数)+パターン 4 つ(バンク 1〜4 の順に、各 ch・各区切りの 192 バイト)+チェックサム(合計 xor $A5)+名前 8(合計 約 6.3KB)。保存後に読み戻して検証。レイアウトを変えたら `SAVE_VERSION` を上げる。**書く前に、そのスロットが ChromaSynth の保存か、全部 `$00`/`$FF` であることを確かめ、そうでなければ書かない**(LSDj が使っている場合)。ヘッダは `MBC5+RAM+BATTERY`, **RAM 128KB**(`-r 4`)。曲の名前は 8 バイト(`NameChars` の添字)で、チェックサムの直後に置く。一覧用に `wSlotNames` へ起動時に写す(VBlank の中で SRAM を読まないため)。スロットの選択は `wSlot`。保存は約 20 フレーム、読み込みは約 9 フレーム(PyBoy で測定)

## 操作系(案)
D-pad/A/B/Start/Select のみ。Patch画面: 項目選択+値増減。Sequencer画面: LSDj/ tracker 風グリッド。

## ピアノロールの描画(リング + 2 つのマップの入れ替え)
- **縦のスクロールはリング**: BG マップは 32 行ある。**音程 p の行は、いつもマップの行 `(1 - p) mod 32`(リング行)**に置く。画面はその 18 行(ルーラー、16 音程、状態行)を、SCY で選んで見せる(窓の先頭の音程を top として k = (-top) mod 32、SCY = 8k。ルーラーは行 k、16 音程は k+1〜k+16、状態行は k+17)。シャドウの行(`wGrid`、32 行ぶん)、描き直しの印(`wRowRender`)、コピーの印(`wMaskV` / `wMaskH`、32 ビット)は、すべてリング行で持つので、窓が動いても有効なまま。
- **1 音程のスクロールは 3 行 + SCY だけ**(`VScrollStep`): 入ってくる音程の行と、ルーラーと状態行を新しい場所に書き、SCY を変える。書く行の 1 つ(上へなら新しいルーラー、下へなら新しい状態行)は誰も見ていない行なので 1 フレーム早く書き、次のフレームで残りの 2 行と SCY を一度に変える(1 フレームに 3 行を書くと VBlank の終わりに近すぎるため)。カーソルを押し続けると、押している間、リピートのたびに窓が 1 行ずつ動く。再生中にプレイヘッドが動いたフレームは、この手順を次のフレームに回す。
- **画面全体の描き直し**(`RollRefreshAll`: ページ替え、チャンネル替え、ループ長の変更、2 音程以上の移動など)は、見えていない方のマップに作り、できあがったら LCDC のビット 3 と SCY を一度に切り替えて見せる。途中の状態(上の行は新しく下の行は古いなど)が画面に出ない。1 行ずつの小さな更新(音符の編集、カーソルの移動)は、見えているマップに先に書く(`wMaskV`)。見えていない方は、描き直しの間だけ使い、そのたびに全部書き直すので、同期はしない。
- 作っている間(`wBuild` = 1)にした編集は、見えていない方にだけ書かれ、入れ替えのあとに見える(入れ替えまで 8 フレームほど)。再生中のプレイヘッドは、画面に出ているページ(`wShSeg` / `wShTick` / `wShSpan` / `wShDiv`)に対して位置を決める。
- メッセージ行(`DrawMsg`)は、両方のマップの状態行(それぞれの窓の位置から計算)に書く。他の画面は `$9800` と SCY = 0 だけを使う(`BuildScreen` が SCY を 0 に戻す)。
- ピアノロールのコードは ROM バンク 1 にある(バンク 0 が足りなくなったため。ROM のバンクは切り替えない)。
- 1 フレームの VBlank に書ける量(約 1,100 マシンサイクル)は、行のコピーが 1 行約 300、プレイヘッドが約 150。**フレームの途中から始まったとき(LY ≥ 146)は 1 行に減らす**(`LimitBudget`)。PATCH 画面の行も、1 フレーム 3 行まで、LY が 148 に来たらやめる。`headless_test.py` / `headless_long_test.py` が、終わりの LY を測る(151 以下)。
- 行の印は 32 ビットのマスクで、最も小さい行を取り出す(`TakeRow`)。以前の 1 行ずつの走査は、使っていないフレームでも 300 サイクルほどかかっていた。
- **ページ替え**(カーソルが次の小節のページに入る、再生のページ追従)は、裏のマップを作らず(`RollRefreshSoft`)、列の要約とルーラーを作り直し、全部の行を描き直す(`RenderPending`、メインループの中で 1 回)が、行は一度シャドウの `wRRBuf` に作り、**シャドウのスロットと比べて、変わったタイルの範囲だけ**を `wSpanLo` / `wSpanHi` に覚える(`CommitRow`)。同じだった行は、コピーしない。コピーは、その範囲だけ(`RollCopySpan`)。予算は「単位」で数え(ルーラー・状態行 = 4、行 = 3 + 変わったタイル数 / 5、1 フレーム 11、再生ヘッドが動いたフレームは 5 引く、LY が遅い開始なら減らす = `LimitUnits`)、音符が少ないページなら 2〜3 フレームでページが替わる。ページ替えと同時に音程の窓が動くなど、一貫性が要る場合は `RollRefreshAll`(裏のマップ)に戻る。
- `TakeRow` は、ROM の表(`LowBitTab`、`tools/gen_lowbit.py` が作る)で最下位ビットを引く。
- 1 フレームの終わり(LY)を `headless_test.py` / `headless_long_test.py` が測る(151 まで、忙しいフレームが数回 152 に届いてもよい)。DIV レジスタの差で測った実測では、何もしないフレームが約 2 ティック、プレイヘッドが動くと約 +3、行のコピーは 1 行約 4 ティック(1 ティック = 256 T サイクル、VBlank は約 18 ティック)。

## シーケンサーの時計(フレームを数える)
- 以前は、メインループが 1 回まわるたびに、時計を 1 フレームぶん進めていた。画面の描き直し(チャンネル替え、分割の切り替え、ループ長の変更)でメインループが 1 フレームより長くなると、その分の時間が失われて、**テンポが遅くなっていた**(PyBoy で、チャンネル替えを続けると、フレームの 25% でメインループが 1 回飛んでいた)。
- 今は、VBlank 割り込みが `wVBlank` を数え(上限 255)、メインループが `di` / `ei` の間でそれを取り出して `wFrames`(1〜4)にする。`SeqTick` は、時計を 256 × `wFrames` 進め、足りなければ**最大 3 ティック**を続けて鳴らす(遅れを取り戻す)。ティックを 2 つ以上まとめて鳴らす場面は、メインループが 1 フレーム以上かかったときだけ。
- `RenderPending` は、フレームの終わり(LY 138〜143)に近づいたら、残りの行を次のパスに回す(メインループが VBlank に間に合わなくなるのを防ぐ)。
- `DrainMidi` は、フレームの先頭(`UpdateUI` の前)ではなく、`VoiceTick` の後に回した(`UpdateUI` の開始を遅らせないため)。リンクの割り込みで目が覚めたときは、そのまま `DrainMidi` だけを呼ぶ。
- 試験(`headless_long_test.py`): チャンネル替え・分割替え・ループ長・音程の移動を 600 フレーム続けても、150 BPM で 300 ティック(誤差 4% 以内)が鳴る(以前は 25% 少なかった)。

## 拍子
- (M17b)ロールの 1 ページは `PageFor` が決める: カーソルまたは再生ヘッドのティック(パターン先頭から数えた絶対ティック)を見せる `wPageAbs`(先頭)・`wPageCols`(使う列数 ≤16)・`wPageSpan`(ティック数)。区切り(`wDivTicks`)が小節(`wBarTicks`)を割り切るなら、1 小節 ≤16 セルは 16/n 小節(整数)、それ以上は小節の頭から 16 セルずつ(最後はずらす)。割り切れなければ 16 セル固定(span の倍数、最後は 384 − span)。ページは 192 ティックの区切りをまたげる(`BuildCols` が次の区切りへ進む)。使わない列は空白。ページはカーソル移動・画面を開く・全再描画のたびに作り直す。
- (M17)拍子とループ小節数は**パターンごと**: `wPatTsn/wPatTsd/wPatBars`(各 `NUM_PATS` バイト)。編集中のパターンだけ、MIDI ブロックの `PM_TSN/PM_TSD` と `wSeqBars` が正(`TsStore` が編集の切り替え・保存の前に配列へ書き、`TsLoadEdit` が編集に入るとき配列から読む)。再生側は `PlayInfo` が `wPlayBank` のパターンについて `wPBarTicks`・`wLoopSeg/wLoopTail` を出す(編集中と同じパターンなら生きている値、違えば配列から)。`SongBarStart` は切り替え後に `PlayInfo` をやり直し、位置 = `wBarIdx × wPBarTicks`(ループの外なら 0)。保存は +6336 の 12 バイト(チェックサム外、0 = 既定)。
- 拍子は、パッチの MIDI ブロックの 2 バイト(`PM_TSN` = 分子 1〜16、`PM_TSD` = 分母の添字 0/1/2 = 4/8/16)で、曲と一緒に保存される。0 / 範囲外は 4/4 として扱う(拍子ができる前の保存は、その位置が `$00` だった)。
- `TsUpdate` が、`wBeatTicks`(12 / 6 / 3)、`wBarTicks`(分子 × 1 拍、最大 192)、`wMaxBars`(384 ÷ 1 小節、最大 15)を計算する。呼ぶのは、起動時、読み込みのあと、MIDI ページの値の変更のあと、ピアノロールを描くとき(`BuildCols`)。
- 小節の数(`wSeqBars`)から、ループの終わり(`wLoopSeg` / `wLoopTail`)を作るのは `ComputeLoopEnd`(以前の表 `LoopEndTab` は無くなった)。`SeqStep` は、ティックごとにこれを呼ぶ。
- ルーラーは、ページの先頭の位置から、拍の位相、小節の中の位置、小節の番号を `BCInitPhases` で求め、1 列ごとに進める(`BuildCols`)。小節線は、小節の頭の列に、拍の目印は、拍の頭の列に出る(ループの外では小節番号だけ)。
- 音符の位置(ティック)は拍子に依存しない。区切り(192 ティック)も同じ。

## 再生中のパターンの切り替え(M14c)
- LOOP モードで再生中に編集パターンを変えると、`SongSetEdit` は、再生するパターンのバンクを変えずに、`wQueuedBank` にだけ入れる(鳴っているパターンに戻したときは 0)。再生していないときは、すぐ `wPlayBank` になる。
- `SeqStep` は、ティックを鳴らす前に、小節の中の位置 `wBarPos` を見る。0 なら、小節の頭で、`SongBarStart` が `wQueuedBank` を `wPlayBank` に移し、鳴っている音を止める。`wBarPos` は 1 ティックごとに 1 増え、`wBarTicks`(拍子の小節の長さ)で 0 に戻る。ループの折り返し、再生の開始、MIDI の開始で 0 にする。
- SONG モードでは、切り替えはチェーンが決める(`wQueuedBank` は使わない)。
- ソング画面の `PLAY` の行は、`wPlayBank`(鳴っているパターン)と、`wQueuedBank`(あれば `NEXT`)を出す。
