# M24 保存スロット画面を「項目を選ぶ」形にして、新規・複製・削除を足す(設計と実装、2026-11-11)

状態: 実装済み(PR は M24 のブランチ `feat/m24-slot-menu`)、自動試験は通過(`tools/headless_slotmenu_test.py`)、**実機は未確認**。

## 1. 願い
スロット画面(START+↓)に、**曲の新規作成・複製(コピー)・削除**を足したい。ボタンの組み合わせでは足りないので、**項目を選ぶ形**にしたい。将来、ここに、**エクスポート / インポート / 送信 / 受信 / 交換**も並べたい(今は構想だけ)。

## 2. いまの画面
4 つのスロットを縦に並べ(`USED` / `FREE`、名前)、↑↓ で選び、**A で読み込み、B で保存**。名前は、下の `NAME` の行で、←→ でカーソル、SELECT+↑↓ で文字を変える。プレイ画面では、SELECT+B / SELECT+A の近道で、現在のスロットへ保存 / 読み込み(これは、そのまま残す)。

## 3. 案: スロットを選んで A → 項目の一覧(メニュー)
```
SAVE SLOTS
 1 TETRIS-ISH   USED
>2 (EMPTY)      FREE
 3 BOSS THEME   USED
 4 (EMPTY)      FREE
 ----------------
 > LOAD
   SAVE
   NEW
   COPY TO...
   RENAME
   DELETE
```
- ↑↓ でスロットを選び、**A でメニューを開く**(カーソルが、メニューへ移る)。メニューは、↑↓ で項目、**A で実行、B で戻る**。
- 項目は、スロットの状態で変わる: 空のスロットでは、`SAVE`・`NEW`・`RENAME` だけ。使用中では、すべて。**項目が増えても、キーの割り当ては、増えない**(将来の `EXPORT`・`IMPORT`・`SEND`・`RECEIVE` も、行を足すだけ)。
- 壊しうる操作(上書きの保存、`DELETE`、`NEW`、上書きの `COPY`)は、これまでと同じ「**もう一度同じ操作**」(約 1.5 秒以内)で確認する(`AGAIN:OVERWRITE` と同じ作り)。
- ほかの画面(プレイ画面など)の SELECT+B / SELECT+A の近道は、変えない。

## 4. 各項目の動き
- **LOAD**: いまと同じ(そのスロットを読み込む)。
- **SAVE**: いまと同じ(使用中なら、確認のあとで上書き)。
- **NEW(新規作成)**: **そのスロットに、空の曲を書き込んで**、現在の曲にする(作業中の曲は、空の曲になる: 全部のパターンが空、音色・BPM・チェーンは初期値、**名前も空**)。
  - **使っていない(曲が入っていない)スロット**で NEW を押すと、そこが「曲の入ったスロット」になり、読み込みも、保存もできるようになる(いまは、新しいスロットで読み込みを押すと「曲が無い」と出る)。
  - **すでに使っているスロット**で NEW を押すと、**既存の曲が空になる**(名前も空)。上書きなので、確認を求める(もう一度、同じ操作)。
- **COPY TO...(複製)**: 選んだスロットの曲を、**別のスロットへコピー**する。行き先は、スロットの一覧から選ぶ(↑↓、A で決定、B で取り消し)。行き先が使用中なら、確認する。コピーは、SRAM のスロットのバイト列を、そのまま、別のスロットへ(曲の中身を、展開しない)。**スロットが 1 つしかない(8 KB の SRAM)カートリッジでは、この項目は出ない。**名前は、同じにする。
- **RENAME**: 名前の編集(いまの `NAME` の行の操作を、この項目の中に入れる)。名前は、曲の一部として、保存と一緒に書かれる。**そのスロットが使用中なら、名前だけを、保存し直さずに変える**(曲の中身は、そのまま)。
- **DELETE(削除)**: そのスロットを**空にする**(8 KB を `$00` で埋める)。**ChromaSynth の曲が入っているスロットだけ**(ほかのソフト、LSDj などの領域には、書かない)。確認が要る。
- スロットの仕組み(曲の保存の形式 v11、`SlotWritable` の規則)は、変えない。

## 5. 将来の項目(今回の作業ではない)
スロット画面は、曲を「出し入れ」する場所としても、使う。**エクスポート**(曲を、Mac のファイルとして取り出す)、**インポート**(Mac のファイルから、スロットへ)、**送信**(別の Chromatic へ、無線で)、**受信**。
- **交換**は、「**送信**と**受信**を、2 台でそろえて行う」ことで、操作としては、同じ。エクスポート / インポートは、Mac のファイルが相手、送信 / 受信は、別の Chromatic が相手、という違い。内部は、どちらも、「スロットの生のバイト列を、ブロックに分けて、検査しながら流す」仕組み(`FUTURE_SYNC_EXPORT.md` の M22)。
- メニューに、`EXPORT`・`IMPORT`・`SEND`・`RECEIVE` の行を足すだけで済むように、メニューを作っておく。

## 6. 作業の見積もり
- ROM(`src/sram.asm` のスロット画面、`src/ui.asm` の描画): メニューの描画と入力。名前の変更は、`RENAME` の中で、スロットに保存された名前を直接書き換え(版 11 ではチェックサムも直す。版 9 は名前がチェックサムの外)、`NEW`・`COPY`・`DELETE`・`RENAME`(名前だけ書き換え)。ROM のバンク 1 の空きは、十分(約 7 KB)。
- 試験: 各項目(空と使用中、確認の 2 回押し、LSDj の領域は壊れないこと、スロットが 1 つのカートリッジ)、既存のスロット画面の試験を、メニュー用に直す。
- 1 つの PR。M19(PR #17)のマージのあとに着手する(スロットの画面と保存は、M19 で変わったので)。

## 7. 決まったこと(2026-11-11、ユーザーの回答)
1. **NEW**: 上の §4 のとおり(そのスロットに空の曲を書き込む。使用中のスロットでは、既存の曲が空になり、名前も空になる)。
2. **COPY TO** の行き先は、**一覧から選ぶ**。
3. スロット画面の A / B の直接操作は、**メニューに置き換える**。ただし、**スロット画面以外**(プレイ画面など、任意の画面)での SELECT+B(保存)/ SELECT+A(読み込み)は、**そのまま使える**。
