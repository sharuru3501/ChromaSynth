# 次の機能の検討(音作りの細分化、画面の「戻る」操作)

ユーザーの要望(2026-11-07)。**実装は、まだしていない。ここは、検討の材料**(何を選ぶかを決めるための、案と、費用、決めてほしいこと)。
ROM を変えるので、どちらも、PyBoy の自動試験 + カードのページ 2 の書き込みが要る(ページ 1 と SRAM は触らない)。聴感・操作感は、実機でユーザーが確認する。

## 1. 音作りを、もっと細かく

**決定(2026-11-07)**: 音は APU だけで鳴らす。動かし方は、当時のゲームや LSDj がやっていたフレーム単位のレジスタ書き換えの範囲に限る。LSDj は「どの効果を入れるか」の基準、M8 Tracker は操作性の考え方の参考にする。ピアノロールなので、効果は音符ごとのコマンドではなく音色のパラメータとして持たせる。
- 入れる: APU の機能すべて(M9a: エンベロープの向き/速さ、音の長さ、パンニング、ノイズの分周比、全体の音量)、アルペジオ・ポルタメント・デューティの切り替え(M9b)、波形エディタ(M9c)。ビブラート・ピッチベンド・ベロシティは残す。
- 入れない: トレモロ、トリガを何度もやり直して作る ADSR(雑音が出やすく GB の作法から外れる)。DAW からの音色操作は M9 の後。
- 下の表は検討の記録。

### いまのパラメータ(`src/ui.asm` の `PT_*`、パッチは 1 チャンネル 8 バイト)
| チャンネル | 行(最大値) |
|---|---|
| CH1 パルス | DUTY(3)、VOL(15)、ENV(15)、SWT/SWD/SWS(スイープの時間・向き・量)、VIBD/VIBS(ビブラートの深さ・速さ) — **8 バイトを使い切っている** |
| CH2 パルス | DUTY、VOL、ENV、VIBD、VIBS(3 バイト空き) |
| CH3 波形 | WAVE(4 種の固定波形)、LVL(出力レベル 3 段)、VIBD、VIBS(4 バイト空き) |
| CH4 ノイズ | WDTH(幅 1 ビット)、VOL、ENV(5 バイト空き) |
| MIDI(5 ページ目) | CH1〜4 の MIDI チャンネル、BEND、VELO、MODW |

### 案(価値 / 費用の見当。決まったら、PATCH_SIZE と SAVE_VERSION を上げ、画面の行を足す)
| 案 | 内容 | 費用・注意 |
|---|---|---|
| **波形エディタ**(CH3) | 32 サンプル(16 バイトの RAM)を、自分で描く。いまは 4 種の固定波形 | 価値が大きい。**CH3 が止まっている間にしか、波形 RAM に書けない**(AGENTS.md ルール 6)ので、書き換えの時の音切れの扱いが要る。保存は 16 バイト増(パッチ 1 つに入らない → PATCH_SIZE の拡張) |
| **デューティ・スイープ(PWM)**(CH1、CH2) | 音の途中で、デューティを動かす(ソフトウェアで、フレームごとに) | 小さい。パラメータ 2 つ(深さ、速さ)で足りる。CH2 の空きに入る |
| **アタック / ディケイの細分化** | いまの ENV(15 段)は、ハードのエンベロープの「ペース」。ソフトウェアで、フェードイン(アタック)、保持(サステイン)、リリースを足す | 中。1 フレームごとの音量の更新(いまのビブラートと同じ仕組み) |
| **ポルタメント(グライド)** | ノートからノートへ、滑らかに | 小〜中。単音の演奏(キーボードの使い方)に合う。1 パラメータ(時間) |
| **トレモロ**(音量の揺れ) | ビブラートの音量版 | 小。VIBD/VIBS と同じ仕組み |
| **ノイズの周波数・分周比**(CH4) | いまは WDTH(幅)だけ。分周比とシフトを選べるように | 小。ノイズは、パーカッションに使うので、価値が大きい |
| **パンニング**(各チャンネルの左右、NR51) | チャンネルごとに、左・中央・右 | 小。ステレオで聴く場合のみ有効(Chromatic のイヤホン出力が、ステレオか要確認) |
| **アルペジオ**(自動で、和音を順に鳴らす) | 1 つのチャンネルで、和音の雰囲気を出す | 中。パラメータ 2〜3 個 |
| **ベロシティの感度**(0〜127 を、どの音量カーブに) | いまは、有効・無効の 2 択(VELO) | 小 |

### 決めてほしいこと
1. **何を、優先しますか**(上の表から、いくつか選んでください。全部は、容量・時間の面で難しいです)。
2. **使い方**: 主にシーケンサーで曲を作る(音色を細かく)か、キーボード(Bluetooth/有線)で弾くか。後者なら、ポルタメント、アタック、ノイズが効きます。
3. **画面**: 1 チャンネルの行が 8 行を超えるので、**ページを増やす**(いまは、5 ページ: CH1〜4 と MIDI)か、1 画面に詰めるか。

## 2. 画面の「戻る」操作

**決定・実装済み(2026-11-07)**: START+→ / START+← で次 / 前の画面(全画面で同じ、一直線)。START 単独は空けておく。キーボード画面も START+← で抜けてシーケンサーへ。SELECT+START はキーボード画面でも再生・停止。下の表は検討の記録。

### いまの操作(`src/joy.asm`)
| 操作 | 動作 |
|---|---|
| START | 画面を、**一方向に進める**(再生 → 音色 → シーケンサー → キーボード → ※キーボードでは START は効かない) |
| SELECT の単押し | 次のチャンネル |
| SELECT+START | シーケンサーの再生・停止(キーボード画面では、約 1 秒の長押しで、再生画面へ抜ける) |
| SELECT+A / SELECT+B | 保存 / 読み込み |
| A(再生・音色)| 発音(ゲート) |
| B + 十字(音色画面) | 試聴する音の変更 |

### 案
| 案 | 動き | 長所 | 短所 |
|---|---|---|---|
| **A: START の長押しで、前の画面へ** | 短く押すと進む。約 0.5 秒押し続けると、戻る | 新しい組み合わせがいらない。わかりやすい | 短押しの反応が、「離したとき」になる(押した瞬間ではなく)。SELECT+START(再生・停止)と区別が要る |
| **B: SELECT+B(いま「読み込み」)を入れ替える** | — | — | 保存・読み込みの誤操作が怖い。**非推奨** |
| **C: B+START** | B を押しながら START で、戻る | 短押しが、いままでどおり、押した瞬間 | B は、音色画面で、他の操作(B+十字)にも使う。シーケンサー画面では、B(離す)で、音符を消す操作と重なる |
| **D: 画面ごとに、「戻る」先を決める**(履歴ではなく、固定の順番を逆に) | 例: START = 次へ、SELECT+START の代わりに … | — | 割り当てが、足りない |

おすすめは **A(START の長押しで戻る)** で、キーボード画面でも、同じ長押しで、前の画面(シーケンサー)に戻れるようにします(いまは、再生画面に戻る)。

### 決めてほしいこと
1. A、C のどちらにしますか(他に案があれば)。
2. キーボード画面を抜けるときは、**前の画面**(シーケンサー)でよいですか。それとも、いまのまま、**再生画面**ですか。
3. 「戻る」の順番は、**進む順の逆**(キーボード → シーケンサー → 音色 → 再生 → キーボード…と、輪になる)で、よいですか。
